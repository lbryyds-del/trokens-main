## 0. 给新对话的核心结论

用户口中的 p 是希腊字母 ρ，对应 `RHO_ENABLE`，不是新增的 p 模块。原 ρ 在 SAV 1-shot 上已有明确的固定权重推理贡献；现在收益小的是叠加在原 ρ 上的新竞争模块。

已经完成的控制实验表明：

1. 原 ρ checkpoint 上，ρ=1 时 HM 80.2148，原逐帧 ρ 为 82.8976，相差 2.6829 个百分点。
2. 把逐帧 ρ 换成有效帧均值，HM 82.9380，只比逐帧高 0.0403。没有证明逐帧变化是主要增益来源。
3. 新 C 模型第 3 轮权重上，关闭新竞争项 HM 82.9420；完整配对竞争 83.0885；共享负参考权重 83.0988；均匀负参考权重 83.0834。
4. 完整配对与均匀权重仅差 0.0052；共享权重与均匀权重仅差 0.0155，相应配对区间均跨零。没有证明精细配对或正 Support 条件化的负参考选择有独立增益。
5. C 方案训练结束按原流程自动选中第 6 轮，最终测试 HM 82.7730，低于原 ρ 重训练基线 82.8976。固定第 3 轮的机制诊断不能替代这一自动选权重结果。
6. 主要解释是新增证据与原 ρ 的正负相对判断重叠，且新增修正同时引入错误。它并没有被证明能识别或清除“被强制解耦出的虚假动作特征”。
7. 下一步只提出了“真假匹配的视觉依赖性诊断”：检验是否分别依赖目标动作局部与共享内容。尚未实施、没有新模块或收益结论。

不要把这些结果归结为“ρ 没用”，也不要继续把“正匹配条件化竞争”写成已验证的核心创新。

## 2. 框架与研究问题

### 2.1 当前研究条件

冻结 DinoTxt ViT-L；Query 与 Support 均开启类别文本条件化（text concat）时空建模。当前 episode 的每个候选类别都会产生相应表示，即使 Query 不包含该类别。

主匹配使用同类条件下的 Query 帧表示和正 Support 帧原型，经双向最大匹配平均（代码中的 BiMHM）形成分数。这不是把多标签任务改成 softmax 单标签分类。

当前主要开关：Query 解耦 ON、Support 解耦 ON、原 ρ ON、m OFF、HoD OFF、CTD OFF、外观增益 1.0。

### 2.2 必须区分的两件事

`Q_k = f(X, e_k)` 只是类别条件化候选表示，不意味着动作 k 存在。

正确的研究问题是：

> 在多标签小样本动作识别中，类别文本条件化能为任意候选动作生成视觉表示，但这种表示未必意味着动作存在。如何利用当前 episode 的允许信息，核验其是否具有充分且有类别判别性的视觉证据？

生成候选表示本身正常，不应要求推理时先知道动作不存在再禁止生成。真正的问题是：不存在类别的候选表示，可能依靠共享姿态、场景或物体而与正 Support 高度相似。

“阅读/做笔记共享手、桌面、坐姿”等解释是研究假设，不是已经逐视频核实的错误机制。

### 2.3 原 ρ 的实际含义

原 ρ 利用 Post Query patch 与同一候选类别下的正/负 Support 帧参考，分别计算计数归一化的平滑最大相似度，再按 Query 的类别条件化空间权重聚合：

`rho[q,k,t] = sigmoid(positive_evidence[q,k,t] - negative_evidence[q,k,t])`

实际实现还包含可学习温度和尺度。原 ρ 不是一个无约束的大型评分网络，也不能把 sigmoid 输出直接视为已校准的类别存在概率。

只用 Support 的允许标签划分正负参考；未知标签不作负例。Query 真值只能用于损失或事后分组，不参与推理时参考选择。

ρ 作用于匹配贡献，没有直接证明它净化了特征或准确定位了动作。

原 m 是另一条 Raw 证据/关系判断分支，与后来探针中的大写 P（仅 Post 正证据）不是同一东西。

## 5. 实验一：原 ρ 是否有效，逐帧变化是否必要？

同一个原 ρ-only 第 3 轮 checkpoint、同一次 forward、同一批 10000 episodes，零训练更新：

| 推理条件 | Base | Novel | HM |
|---|---:|---:|---:|
| 原逐帧 ρ | 84.7549 | 81.1200 | 82.8976 |

| ρ=1，取消 ρ 修正 | 82.1189 | 78.3969 | 80.2148 |

结论：

- 原 ρ 的固定权重推理贡献约 2.6829 HM 点。
- 时间均值只改变 +0.0403，不能把主要收益归因于精细逐帧置信度。
- ρ=1 的 80.2148 不是重训练关闭 ρ 的 80.1600。
- 平均的是 sigmoid 后的有效帧 ρ，不是先平均 logits 再 sigmoid。
- 验证了权重不变、ρ=1 严格恢复 base logits、历史预测精确复现。

时间统计：有效 Query-class 记录的 ρ 时间标准差均值 0.03237；正类 0.03009，负类 0.03361；时间标准差 >0.1 的比例约 2.28%。约 250000 条 Query-class 记录中，有 2000 条没有有效 relation，其余约 24.8 万条可用。时间差异小不等于 ρ 不重要。

## 9. C 方案：已经实现并重新训练

用户先要求只改代码、自己启动；随后用户实际启动完成了 C 训练。

配置：`configs/trokens/sav_competition_c_s1.yaml`，继承 `sav.yaml`；当前解析后主要差异为竞争开关与输出目录。继承源是可变文件，历史复现实验必须看保存配置。

核心代码：`trokens/models/pair_competition.py`，接入 `text_concat_conditioning.py`，另有配置、checkpoint 语义签名和诊断日志支持。

计算如下（省略类别索引；q/p/n 均作安全单位归一化）：

```text
a[u,r] = stopgrad(softmax_r(cos(p[u], n[r]) / tau))
C[t,u] = cos(q[t], p[u])
E[t,u] = sum_r a[u,r] * cos(q[t], n[r])
R[t,u] = tau * softplus((E[t,u] - C[t,u]) / tau)
B = min(C * original_rho_mass, C)
B_new = B - lambda * R
z_new = z_original_rho + 10 * (BiMHM(B_new) - BiMHM(B))
```

- τ=0.1，最终 λ=0.5；评估使用完整强度。
- 保留原正原型、主池化、原 ρ、原损失。
- C 的比较输入 `DETACH_INPUTS=False`，新比较路径回传到主 Post 表示；DinoTxt 仍冻结。
- 原 ρ 的 `LEARNED_VERIFIER.DETACH_INPUTS=True` 不变。
- 负参考选择权重本身 stop-gradient；每次 forward 重新计算。
- 没有新增独立可学习竞争头，也没有新增专门竞争辅助损失。
- 既有损失为 global + 0.6 base + 0.4 final + 0.05 rho MIL。
- 缺正/负参考、未知标签、无效帧时按规则零惩罚。
- λ=0 精确回到原 ρ 分数。

注意：控制 `DETACH_INPUTS=True` 的含义是切断新比较特征的梯度，不应未经核实就称为“整个新增修正对主网络完全没有梯度”。修正还包含可导主匹配矩阵与 max 选择；若以后要隔离整个 Δz 的梯度，需要按实际计算图单独审计。

`docs/pair_competition.md` 是实现时文档，里面“没有启动实验”的状态文字已经过时；实验完成状态以本交接及输出文件为准。

第一行绝不是原 ρ 重新训练 baseline。均匀权重只取消基于正 Support 相似度的参考选择，不取消正匹配、正负 Support 标签或原 ρ。

平均惩罚是每个 Query-class 自适应 offset，不是对所有样本减同一个常数。它不改变帧匹配赢家，但可改变不同 Query 之间的排序。

配对 episode bootstrap，2000 次，单位为 HM 百分点：

| 比较 | 差值 | 固定视频池条件下 95% 区间 |
|---|---:|---|
| 完整配对 − 关闭新竞争项 | +0.1466 | [+0.0833, +0.2080] |
| 完整配对 − 平均惩罚 | +0.0388 | [+0.0110, +0.0662] |
| 完整配对 − 共享权重 | -0.0103 | [-0.0251, +0.0045] |
| 共享权重 − 均匀权重 | +0.0155 | [-0.0396, +0.0683] |
| 均匀权重 − 关闭新竞争项 | +0.1414 | [+0.1012, +0.1853] |
| 完整配对 − 均匀权重 | +0.0052 | [-0.0512, +0.0577] |

区间跨零意味着没有清晰优劣证据，不是严格等价检验；这些也不是跨训练 seed、独立新视频或其他数据集的置信保证。

## 12. 新竞争收益小的诊断证据

### 12.1 修复与误伤相互抵消

同 episode、同类别的正负 Query 排序比较共 243458 对：

| 方法 | 错误对数 | 修复原错误 | 引入新错误 | 净减少 |
|---|---:|---:|---:|---:|
| C 权重仅原 ρ | 41342 | — | — | — |
| 完整配对 | 41024 | 2335 | 2017 | 318 |
| 平均惩罚 | 41072 | 2656 | 2386 | 270 |
| 共享权重 | 41003 | 2316 | 1977 | 339 |
| 均匀权重 | 40826 | 1478 | 962 | 516 |

完整配对新增错误数相当于修复数的 86.4%。排序错误率从 16.981% 到 16.851%，不是大幅下降。错误对数与 AP/HM 的权重不同，不能由净修复数直接推断哪种 HM 必然更高。

完整配对 logit 平均变化：正样本 -0.1519，负样本 -0.4713；均匀方式：正样本 -0.1099，负样本 -0.4784。模块有实际作用，不是没开或没过 warmup。

### 12.2 主要改变边界排序

从保存分数只读计算，完整配对：

- 修复对的原始分差绝对值中位数：0.0881。
- 被改错对：0.1001。
- 仍未修复错误对：0.8203。
- 只修复原错误的约 5.65%，且另引入大量新错误。

它主要影响原本分数接近的样本，对大分差错误帮助有限。

### 12.3 不能把不同负参考方案都解释为“权重没生效”

- 完整配对 vs 共享权重：修正相关系数 0.99925，logit 平均绝对差 0.00682，逐帧细分在输出上几乎冗余。
- 共享权重 vs 均匀权重：修正相关系数约 0.83433，平均绝对差约 0.13815，确实改变了分数，但没带来可靠 HM 优势。
- 新竞争有效比例：负 Query-class 帧对约 99.99%，正样本约 97.75%；并非主要因为大量样本找不到负参考。

这些补充统计来自 `competition_c_uniform_reference_test_20261105_v1/paired_scores.npz` 的终端只读计算，不是新训练。

### 12.4 当前机制解释：哪些是推断

优先级较高的解释是：

1. 新项与原 ρ 复用正负相对相似度，新增信息有限；但尚未测出完整条件互信息，不能宣称绝对信息饱和。
2. “负 Support 像正 Support”不等于它能可靠反驳当前 Query 的目标动作。新权重由 P-N 相似度决定，同一正帧的权重用于不同 Query。
3. 视频级负标签不意味着该视频的全部局部内容都是目标动作的反证。共享坐姿、桌面、手部可能同时存在于真阳性中。
4. 原 ρ 已读取 Query patch；新竞争使用池化帧特征，增加时间矩阵修正不等于增加更细的空间证据。
5. 新比较能回传，但没有专门的可靠反证监督。尚无严格“整个新增修正停止梯度 vs 允许梯度”的重训练对照，不能断言回传无效。

共享内容造成误伤是与实现、统计相符的机制假设，尚未通过逐视频及局部干预证实。

## 13. 最近追加的只读诊断：原 ρ 接近时，什么已有指标还有效？

本次用的是**原 ρ-only checkpoint 的历史缓存**，不是 C 权重：

`output/sav/post_evidence_probe_20261104_152720/cache/{validation,test}/worker*.npz`

在同 episode、同候选类别内组成正 Query 与负 Query 对，要求：

- 双方 8 帧 relation 都有效；
- 8 帧 ρ 向量平均绝对差 ≤0.05；
- base logit 差绝对值 ≤0.25；
- 原 ρ 最终 logit 差绝对值 ≤0.25。

10000 测试 episodes 中筛得 2052 对，来自 1745 个 episodes。只统计候选标量是否把正 Query 排前，并列记半分，不拟合分类器、不改模型预测：

| 候选标量，高值排前 | 正 Query 排前比例 |
|---|---:|
| ρ 时间均值（对照） | 54.5809% |
| 原最终分数（对照） | 51.6569% |
| 原正证据的时间均值 | 51.5107% |
| 原正证据时间下四分位数 | 51.8519% |
| 正证据时间稳定性（负标准差） | 52.6316% |
| 每个 Query 帧 top1-top2 Support 帧相似度差的均值 | 50.9990% |
| 每个 Query 帧最大匹配与平均匹配之差的均值 | 51.4620% |
| 双向互为最佳帧匹配比例 | 51.5595% |
| 每帧最佳相似度的时间稳定性（负标准差） | 52.5828% |

ρ 向量接近阈值改成 0.03/0.10 时分别有 900/4118 对，没有出现稳定的大幅分离能力。训练侧 validation 在 0.05 条件下仅 61 对，不足以据此强选一个指标。

这是有限候选的一维描述性筛查，不是正式条件独立检验，也不排除非线性组合可能有效。样本重复、筛选依赖已有分数，结果不能称为新方法准确率或 mAP。

这段分析此前仅在终端内运行，没有独立的正式 `result.json` 或新 GPU 实验。本交接保存了筛选定义与数值，后续可据缓存重算。

## 14. 目前可以说、不能说的结论

### 可以说

- 原 ρ 在已测原 checkpoint 的推理中有明确贡献。
- 精细逐帧 ρ 变化不是该 checkpoint 上主要收益的必要条件。
- 仅正证据不能替代正负相对证据；简单增加正证据强度没有显示优势。
- 新竞争项在固定 C 权重上有约 0.14–0.16 HM 的小幅修正收益。
- 当前精细配对、正 Support 定向负参考选择没有显示可靠的独立优势。
- 完整 C 训练按原选权重流程本次没有超过原 ρ。

### 不能说

- 已经清除了 Query 中不存在类别的特征，或已经证明假阳性均由共享背景造成。
- 原 ρ 没有用，或所有时序建模、所有负参考条件化方法都无效。
- 固定 C 权重关竞争项就是独立重训练 baseline。
- 推理均值/均匀/关闭开关等于分别重新训练了这些模型。
- 当前结果证明竞争梯度改善了表示，或证明它完全没有改善。
- 通过测试池反复诊断、事后挑 checkpoint 得到的最高分是无偏最终提升。
- 最高注意力区域就是真实动作区域，或“匹配赢家改变”就证明新机制正确。
- HM 相近意味着两种修正逐项相同；共享与均匀的评分确有差别。

## 15. 下一步讨论方向：尚未实施

新的问题应是：

> 当原 ρ 和最终匹配分数接近时，真阳性与假阳性取得这个分数，是否依赖不同的视觉内容？

优先检查：

1. 在剩余错误视频中，目标动作关键细节是否可见。例如手部、人—物关系、动作过程，而不仅是桌面或坐姿。这些例子不是已核实定位结果。
2. 真阳性是否更多依赖可区分目标动作的局部证据；部分假阳性是否主要依赖共享内容。
3. 若这种差异存在，再考虑局部证据依赖性的核验模块，而不是直接再加一个正负分数。

建议的诊断（**未做**）：固定 checkpoint，比较弱化候选动作局部、弱化共享内容、匹配面积/数量/可见性的随机扰动，并检查正负 Query 分数响应。

约束：

- 不能把当前注意力直接当作真实区域；需要独立核验候选位置。
- 干预只是模型依赖性检查，不是可识别的真实世界因果结论。
- 真动作也可能依赖上下文，不能规定“依赖背景=错误”。
- 必须检查多动作真阳性是否受损；不能只挑成功假阳性案例。
- 区域/阈值/方法选择不能用测试 Query 真值做推理选择；测试真值只用于事后分析。
- 如果细节不可观测，不能靠新公式凭空恢复。可能需要反思表示或数据可观测性，但目前还没有据此修改编码器。
- 这不是已经确定的论文创新，也没有保证收益。新对话应先讨论、核查，再请求或等待用户授权实施。
